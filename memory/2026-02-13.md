### What I Built: Order Management Dashboard

**Location:** `/portal/orders` in FFM Website  
**PR:** https://github.com/FitFocusMedia/ffm-website/pull/1  
**Status:** Deployed to production (GitHub Pages)

**Features:**
1. **Order Table View**
   - All content orders in chronological order
   - Columns: Date, Customer, Organization, Event, Package, Amount, Status, Actions
   - Color-coded status badges (paid=blue, delivered=green, pending=gray, refunded=red)
   - Responsive design with hover states

2. **Advanced Filtering**
   - Organization dropdown (all organizations from database)
   - Status filter (pending, paid, processing, delivered, refunded)
   - Date range (from/to)
   - Search box (searches customer name, email, phone)
   - Filters work together (AND logic)

3. **Order Detail Modal**
   - Click "View" on any order to see full details
   - Customer Information section (name, email, phone, Instagram, division, coach)
   - Order Information section (org, event, package, amount, status, timestamps)
   - Payment Information section (Stripe session ID, payment intent ID)
   - "Mark as Delivered" button for paid orders

4. **Quick Actions**
   - Mark orders as delivered with one click
   - Updates status to 'delivered' and sets delivered_at timestamp
   - Table refreshes automatically after status change

5. **CSV Export**
   - Export button generates downloadable CSV
   - Exports currently filtered orders
   - Filename: `orders-YYYY-MM-DD.csv`
   - Columns: Date, Customer, Email, Phone, Organization, Event, Package, Amount, Status

6. **Revenue Tracking**
   - Real-time revenue calculation in header
   - Shows: "X orders • $Y.YY AUD revenue"
   - Only counts paid and delivered orders
   - Updates dynamically with filters

**Integration:**
- Reads from `content_orders` table
- Joins with `organizations`, `events`, `packages` for display names
- Uses Supabase client (existing auth setup)
- Added "Orders" tab to portal navigation (after Content)

### Technical Notes
- Modal uses `onClick` propagation stopping to prevent backdrop clicks closing when clicking modal content
- Date filtering includes end date's full day (adds T23:59:59)
- Search is case-insensitive and checks all customer fields
- Status badges use Tailwind arbitrary values for custom colors
- CSV generation uses Blob + URL.createObjectURL (client-side, no backend needed)
